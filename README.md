# vocal-remove：AI 去人声 / 音源分离（推理 + 训练）

把一首歌拆成 **人声 / 鼓 / 贝斯 / 其他乐器** 四轨，再把除人声外的三轨加起来得到伴奏。

| 文件 | 作用 |
|---|---|
| `remove_vocals.py` | 推理：用预训练的 Demucs，或用你自己训练的检查点，去掉人声 |
| `model.py` | 模型定义（自研的 `MiniDemucs`，以及加载预训练 `htdemucs` 用于微调），检查点读写，长音频分段推理 |
| `train.py` | 训练 / 微调：数据加载、重混增强、损失函数、训练循环、验证 SDR、断点续训 |

---

## 1. 快速使用（推理）

环境：Intel Mac 上 PyTorch 最高支持到 2.2.2，且需要 Python ≤ 3.12，所以用 conda 建了独立环境：

```bash
conda create -n vocal-remove python=3.11
conda activate vocal-remove
pip install torch==2.2.2 torchaudio==2.2.2 demucs==4.0.1 soundfile "numpy<2"
# 还需要系统里有 ffmpeg（brew install ffmpeg）
```

```bash
python remove_vocals.py "周慧敏+-+最爱.mp3"                 # 只输出伴奏
python remove_vocals.py song.mp3 --keep-vocals              # 同时输出人声
python remove_vocals.py song.mp3 -m htdemucs_ft --shifts 5  # 质量更好，速度更慢
python remove_vocals.py song.mp3 -o my_dir --bitrate 192k   # 指定输出目录和码率
python remove_vocals.py song.mp3 -c runs/mini/best.pt       # 用自己训练的模型
```

输出：`output/<歌名>_伴奏.mp3`，加了 `--keep-vocals` 时还有 `output/<歌名>_人声.mp3`。
第一次运行会自动下载预训练模型（约 80MB）。在 CPU 上处理一首歌大约要 6 分钟。

## 2. 训练自己的模型

### 2.1 准备数据

每首歌一个目录，里面放各个音轨的 wav（44.1kHz）。混合音轨**不需要**提供，训练时直接把各轨相加得到。

```
data/
  train/<歌名>/drums.wav  bass.wav  other.wav  vocals.wav
  test/<歌名>/ drums.wav  bass.wav  other.wav  vocals.wav
```

公开数据集 **MUSDB18-HQ**（150 首，约 10 小时，<https://zenodo.org/records/3338373>）解压后就是这个结构。
你自己的多轨工程（比如 DAW 里导出的分轨）也可以照这个结构放进去。

### 2.2 训练命令

```bash
# A. 从零训练 MiniDemucs（约 2000 万参数，需要 GPU 训练若干天才能接近可用水平）
python train.py --data data --out runs/mini --epochs 100 --batch-size 8 --amp

# B. 在自己的数据上微调 Meta 预训练的 htdemucs（学习率要小，显存要求高）
python train.py --data data --arch htdemucs --lr 1e-5 --batch-size 2 --out runs/ft --amp

# 断点续训
python train.py --data data --out runs/mini --resume runs/mini/last.pt

# 小显存 / 快速冒烟测试
python train.py --data data --channels 32 --depth 4 --segment 4 --batch-size 4 --epoch-size 200 --epochs 2
```

每轮训练结束会打印验证集上每个音轨的 SDR（dB，越高越好），并保存：

- `runs/xxx/last.pt`：最新状态（用于续训）
- `runs/xxx/best.pt`：验证损失最低的模型（用于推理）

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--arch` | `mini` | `mini` 从零训练 / `htdemucs` 微调预训练模型 |
| `--channels` `--depth` | 48 / 5 | MiniDemucs 宽度与深度，决定参数量与感受野 |
| `--segment` | 6.0 | 每个训练样本的秒数（htdemucs 固定 7.8s） |
| `--epoch-size` | 2000 | 每轮随机抽取多少个片段 |
| `--stft-weight` | 0.5 | 多分辨率频谱损失的权重 |
| `--no-remix` | 关 | 关闭跨歌曲重混（不建议关闭） |
| `--amp` | 关 | CUDA 混合精度，省显存、提速 |

> **硬件提示**：分离模型的训练量很大。Intel Mac 的 CPU 只适合做冒烟测试，正式训练请用 NVIDIA GPU（比如云服务器或 Colab）。训练好的 `best.pt` 可以拷回 Mac，用 CPU 做推理。

## 3. 原理：一切媒体都是向量

### 3.1 万物皆向量

计算机里所有的媒体，最终都是**一串数字**，也就是一个高维空间里的**向量（张量）**：

| 媒体 | 原始表示 | 向量空间 |
|---|---|---|
| 音频 | 每秒 44100 个采样点，每个点是 -1~1 的振幅 | 一首 4 分钟的立体声歌曲 ∈ ℝ^(2 × 10,584,000) |
| 图像 | 每个像素的 R、G、B 亮度 | 1080p 照片 ∈ ℝ^(3 × 1080 × 1920) |
| 视频 | 图像按时间排成序列（再加一条音轨） | ℝ^(T × 3 × H × W) |
| 文本 | 字/词 → 编号 → 查表得到 embedding | 每个 token ∈ ℝ^d，一句话 ∈ ℝ^(n × d) |

一旦变成向量，“处理媒体”就变成了**在向量空间里做几何运算**：加法、投影、旋转、换基、求距离。
这些运算对任何媒体都适用，只是不同媒体的“好坐标系”不一样。

### 3.2 混音是“力的合成”，分离是“力的分解”

物理里，几个力作用在同一点上，合力就是这些力的**向量和**。声音也一样：空气中的声压满足**线性叠加原理**，录音和混音本质上就是把各个声源的波形逐点相加：

```
mix(t) = drums(t) + bass(t) + other(t) + vocals(t)
   x   =    s₁    +    s₂   +    s₃   +    s₄          (都是 ℝ^(C×T) 里的向量)
```

去人声，就是已知合力 `x`，要求出分力 `s₄`（人声），再用 `x − s₄` 得到伴奏。

但这里有个根本难点：**一个方程，四个未知向量，解有无穷多个。** 就像只知道合力，而不知道各个分力的方向，没法唯一地分解。所以必须给分力的“方向”加上约束，也就是**先验知识**：人声长什么样，鼓长什么样。

- **传统方法 = 人手写的先验。** 例如“左右声道相减”法，它假设人声在立体声的正中间（左右完全相同），于是 `L − R` 正好把人声抵消掉。这其实是一个固定的线性投影，把向量投到“侧向”子空间。问题在于：贝斯、底鼓通常也混在正中间，会被一起消掉；带混响的人声也不完全居中，又会残留下来。
- **深度学习 = 从数据里学出来的先验。** 神经网络看过成千上万首“混合 → 各分轨”的例子，学到一个非线性映射 `f(x) ≈ (s₁, s₂, s₃, s₄)`。它学到的就是“哪些方向属于人声，哪些属于鼓”，并且这些方向会随着内容动态变化。

### 3.3 换个坐标系，分量就分开了：时频域与掩码

在波形（时域）空间里，人声和伴奏的向量高度纠缠，并不正交。
做一次**短时傅里叶变换（STFT）**，相当于换一组基：用“某一时刻、某一频率的正弦波”当坐标轴。在这组新坐标下，有一个经验事实：

> **在同一个时频点上，通常只有一个声源占主导**（W-disjoint orthogonality，时频稀疏性）。

所以分离可以近似成：给每个时频点乘一个 0~1 之间的权重，也就是**掩码（mask）**，把属于人声的格子留下，其余的置零，然后做逆变换回到波形。
这在几何上是一个**对角投影算子**。神经网络要做的，就是为每首歌、每个时刻预测出这个投影该怎么做。

`htdemucs` 同时在两个坐标系里工作（下文 3.5 节）。本项目的 `MiniDemucs` 只在时域工作：它让卷积层自己学一组“可训练的基”，作用类似于 STFT，但是是为分离任务量身定制的。

### 3.4 同一套思想用在其他媒体上

“向量化 → 在合适的空间里分解 / 投影 / 切割”是通用的范式：

- **图像**：抠图 `I = α·前景 + (1−α)·背景` 和混音是同一个形式，α 就是掩码；风格迁移是把“内容”和“风格”分解到不同的特征子空间。
- **视频**：背景建模常用 **低秩 + 稀疏分解**（RPCA）：`视频矩阵 = 低秩部分(静止背景) + 稀疏部分(运动前景)`，这是在矩阵空间里做“分力分解”。
- **文本**：词向量满足近似的线性关系 `king − man + woman ≈ queen`；在句子的 embedding 空间里，可以减去“话题方向”保留“情感方向”，也可以用聚类、主题模型把文档分解成若干主题分量。
- **多模态**：CLIP 一类模型把图像和文本映射到**同一个**向量空间，“以文搜图”于是变成了求两个向量的夹角。

> 说明：本文的“力学”是类比，不是真的物理模拟。准确的说法是**线性代数 / 几何**（向量加法、投影、换基），再加上**神经网络从数据中学到的非线性先验**。之所以能用“合力与分力”来类比，前提是声音满足线性叠加，这在物理上是成立的。

### 3.5 模型结构

#### MiniDemucs（`model.py`，从零实现）

```
mix (B, 2, T)
  │ 归一化：减均值、除标准差（让模型不受音量影响）
  ▼
Encoder ×5   Conv1d(k=8, s=4) → ReLU → Conv1d(1×1) → GLU      时间 ÷4、通道 ×2
  │  每层输出 ────────────────┐ 跳跃连接（skip connection）
  ▼                           │
BiLSTM（瓶颈层）              │  让每个时间步看到整段约 6 秒的上下文
  ▼                           │
Decoder ×5   (x + skip) → Conv1d(3) → GLU → ConvTranspose1d(k=8, s=4) → ReLU
  ▼
(B, 4 音轨, 2, T)  × std + mean 还原音量
```

- **编码器 = 学出来的“换基”**：第一层卷积核长 8 个采样点，作用像一组可训练的滤波器组。越往深层，时间分辨率越粗、通道越多，表示的是越抽象的“这里有人声 / 这里是鼓点”。5 层之后时间压缩了 4⁵ = 1024 倍。
- **GLU 门控**：`a ⊙ σ(b)`，其中一半通道决定“让多少信号通过”。这本身就是一个可学习的**软掩码**。
- **BiLSTM**：卷积只看局部；LSTM 能在整个片段上来回传递信息，从而判断一段持续的音高更像人声还是合成器。
- **跳跃连接**：深层只知道“是什么”，丢掉了“精确在哪里”。把编码器同层的细节直接加回解码器，就能还原出采样点级别的波形。
- **输出直接是波形**，因此不存在“频谱掩码丢掉相位”的问题，这也是时域模型的一大优势。

#### htdemucs（Meta，推理时默认使用，也可以拿来微调）

**混合（Hybrid）**：一条分支在时域上像上面那样做卷积，另一条分支在 STFT 频谱上做卷积。两条分支在最深处通过 **跨域 Transformer**（自注意力 + 交叉注意力）交换信息，最后把两个分支的输出相加。它兼得了频谱分支在频率上的精确和时域分支在相位、瞬态上的精确，是目前效果最好的开源模型之一（MUSDB18 上平均 SDR 约 9 dB）。

### 3.6 训练机制（`train.py`）

1. **重混增强（remix）——利用了线性叠加**
   既然 `mix = Σ 音轨`，就可以把 A 歌的鼓、B 歌的贝斯、C 歌的人声随意组合，生成一首“新歌”，而且标签天然正确。150 首歌因此能组合出近乎无穷多的训练样本。这是音源分离训练里最重要的技巧。
   此外还有：随机音量（0.25~1.25 倍）、极性翻转（`−x` 听起来一样）、左右声道互换。
2. **损失函数**
   - 波形 L1：`|ŝ − s|`，逐个采样点对齐，相位、瞬态都必须准确。
   - 多分辨率 STFT 损失：在 512 / 1024 / 2048 三种窗长下比较幅度谱（谱收敛 + 对数幅度）。它更接近人耳的感知，能抑制“听得见的残留”。
3. **评价指标 SDR**：`10·log10(‖s‖² / ‖s − ŝ‖²)`，也就是目标向量的长度与误差向量长度之比，单位是分贝。
4. **优化**：AdamW + 线性预热 + 余弦退火，梯度裁剪；可选 CUDA 混合精度。

### 3.7 推理机制

- **分段 + 重叠相加（overlap-add）**：整首歌太长，放不进模型。所以切成和训练时一样长的片段，相邻片段重叠 25%，重叠部分用三角窗加权平均，避免接缝处出现咔哒声（`model.separate_long`）。
- **shifts（仅限预训练模型）**：把输入随机平移几次，分别推理后再平均。这利用了“平移输入 → 输出也只是平移”的性质来降低误差，代价是速度成倍变慢。
- **伴奏 = 鼓 + 贝斯 + 其他**：`remove_vocals.py` 用的是“全部音轨之和 − 人声”，两种写法等价。

## 4. 常见问题

- **伴奏里还有一点人声？** 换 `-m htdemucs_ft`，或者调大 `--shifts`；也可以用含有你目标曲风的数据去微调 htdemucs。
- **从零训练的 MiniDemucs 效果不如 htdemucs？** 正常。后者用了更多数据、更大的模型和混合结构。MiniDemucs 的主要价值在于看清完整的训练流程，以及在特定数据上做实验。
- **采样率不是 44.1kHz？** 先转一下：`ffmpeg -i in.wav -ar 44100 out.wav`。
